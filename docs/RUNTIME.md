# Persistent Runtime

`0-1` can run continuously with:

```bash
npm run compete:loop
```

The loop is designed for one small always-on VM and systemd. It is intentionally not a distributed scheduler.

## Delivery semantics

Live execution uses **at-least-once** handoff semantics.

For every qualified live opportunity:

```text
qualified decision
-> persist to data/runtime/runtime-state.json as pending
-> attempt bounded execution
-> on transaction hash: record trade and clear pending
-> on failure/crash: leave pending
-> next process/cycle retries pending work while the belief remains valid
```

This means work is not silently dropped because the process crashed after selection.

At-least-once delivery can produce a duplicate economic action after an ambiguous network failure where the transaction landed but the client never received the hash. The per-order TST cap, per-cycle TST budget, fresh quote/risk checks, and market/outcome cooldown bound that risk. This is intentionally not an exactly-once claim.

## Multiple trades per cycle

A cycle is not capped to one trade. After pending work is retried, the hunter ranks fresh actionable opportunities and the runtime can execute multiple distinct market/outcome opportunities until `ZERO_ONE_MAX_CYCLE_TST` is exhausted.

Each live decision is revalidated through `executeBoundedBuy` immediately before submission:

- market must still be open;
- current implied probability must be available;
- prior drift must remain within policy;
- fresh `quoteBuy` must fit the order cap;
- confidence/edge/price-impact/exposure policy must still pass;
- token approval is bounded to the slippage-capped amount.

## State

Default durable state:

```text
data/runtime/runtime-state.json
```

It contains cycle counters, pending trade work, recent transaction hashes, and market/outcome cooldown timestamps. Writes are atomic.

The runtime lock defaults to:

```text
data/runtime/compete.lock
```

A second loop process exits while the active PID owns the lock. A stale lock is reclaimed after a crash/reboot.

## Cadence

Defaults:

```text
ZERO_ONE_CYCLE_INTERVAL_MS=180000
ZERO_ONE_FAILURE_BACKOFF_MS=30000
ZERO_ONE_PENDING_RETRY_MS=30000
ZERO_ONE_MARKET_COOLDOWN_MS=1800000
ZERO_ONE_MAX_ORDER_TST=5
ZERO_ONE_MAX_CYCLE_TST=20
```

Pending trades are retried before fresh hunting. Expired beliefs are discarded and must be regenerated by a new hunt rather than executed from stale reasoning.

## systemd

Install on Ubuntu from the repository root:

```bash
sudo bash deploy/install-ubuntu.sh
```

Edit `/opt/zero-one/.env`, then:

```bash
sudo systemctl restart zero-one
sudo systemctl status zero-one
journalctl -u zero-one -f
```

The service has `Restart=always` and is enabled for boot, so SSH disconnects, process failures, and ordinary instance reboots do not stop the agent permanently.

## Live enablement

The service can run continuously in shadow mode with:

```text
ZERO_ONE_LIVE_TRADING=false
```

When the registered competition wallet is funded and signing is configured, live bounded execution is explicitly enabled with:

```text
ZERO_ONE_LIVE_TRADING=true
ZERO_ONE_KILL_SWITCH=false
```

Emergency stop:

```text
ZERO_ONE_KILL_SWITCH=true
```

The loop may continue researching while the kill switch prevents `buyShares`.
